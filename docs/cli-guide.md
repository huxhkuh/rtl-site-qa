# RTL Site QA

כלי בדיקת איכות קטן לאתרי אינטרנט, עם דוח בעברית, צילומי מסך ויציאה מתאימה ל־CI. מבוסס Node.js ו־Playwright; אין שירות ענן, מסד נתונים או צורך בשינוי קוד האתר.

## התחלה מהירה

נדרשים Node.js 22 ומעלה ו־Chromium של Playwright. פותחים מסוף בתיקיית הכלי:

```sh
npm ci
npx playwright install chromium
npm run qa -- --base http://localhost:3000 --pages /,/about,/contact
```

מול sitemap ועם תיקיית תוצאה קבועה:

```sh
npm run qa -- --base https://your-site.example --sitemap /sitemap.xml --out runs/release-1 --max-pages 30 --fail-on high
```

דוח `report.html`, נתונים `report.json`, ותיקיית `screenshots/` נוצרים באותה תיקייה. יש להעביר אותם יחד. אפשר לפתוח את HTML ישירות בדפדפן; אין תלות בפונטים או בסקריפטים חיצוניים. מומלץ תיקייה חדשה לכל ריצה, לשמירת היסטוריה.

## קובץ הגדרות

שמרו `qa.config.json` לצד הפרויקט. נתיבים בקובץ ההגדרות נפתרים ביחס לתיקייתו; `--out` נפתר ביחס למסוף.

```json
{
  "baseURL": "http://localhost:3000",
  "pages": ["/", "/about", "/contact"],
  "sitemap": ["/sitemap.xml"],
  "crawl": true,
  "maxPages": 20,
  "maxLinks": 200,
  "maxSitemaps": 10,
  "exclude": ["/logout", "/checkout", "/cart", "/delete", "/api/", "*preview=*"],
  "viewports": [
    { "name": "mobile", "width": 390, "height": 844 },
    { "name": "tablet", "width": 768, "height": 1024 },
    { "name": "desktop", "width": 1440, "height": 900 }
  ],
  "failOn": "high",
  "outDir": "qa-runs/release-1",
  "baselineDir": "qa-baselines",
  "allowedResourceOrigins": [],
  "maskSelectors": ["input", "textarea", "[data-qa-private]"],
  "visual": { "enabled": true, "maxDiffRatio": 0.01, "pixelThreshold": 0.15 }
}
```

```sh
npm run qa -- --config qa.config.json
```

- `pages` ו־`sitemap` מתאחדים; עמודי תרחישים נוספים לרשימה. כדי להשתמש רק במפת אתר הגדירו `pages: []`.
- `crawl: false` בודק רק עמודים מוגדרים ומפות אתר. קישורים שנמצאו בהם עדיין נבדקים ב־GET, בלי להוסיף אותם לסריקת DOM.
- תחום הסריקה הוא **אותו origin בדיוק**: פרוטוקול, שם מארח ופורט. תתי־דומיין, פורט אחר או מעבר מ־HTTP ל־HTTPS אינם מאושרים אוטומטית. הזינו את כתובת היעד הסופית.
- כתובות מנורמלות: סידור פרמטרי query, הסרת fragment ופרמטרי מעקב (`utm_*`, `gclid`, `fbclid`). פרמטרים אחרים נשמרים. מסלולים עם ובלי `/` בסוף עשויים להיות שונים ולכן אינם מאוחדים.
- `exclude` מחליף את רשימת ברירת המחדל. בלי `*` מתבצע חיפוש תת־מחרוזת במסלול וב־query; עם `*` מתבצעת התאמה מלאה למסלול+query או ל־URL. הוסיפו כתובות GET בעלות השפעה עסקית.
- `allowedResourceOrigins` מאפשר לטעון קבצים ונתוני GET מ־CDN מסוים; הוא אינו מרחיב ניווט, קישורים או sitemap לדומיין נוסף. חסימות מופיעות בדוח.
- קיימות מגבלות זמן, 10 קפיצות redirect, עד 12,000 רכיבי DOM לבדיקה, גלילה מוגבלת (`maxScrollSteps`, ברירת מחדל 12), ומספר לחיצות Tab מוגבל (`keyboardSteps`, ברירת מחדל 12).
- `ignoreChecks` הוא מערך מזהי בדיקות לדילוג, למשל `["heading-h1"]`. החרגות נשמרות בדוח. אין השתקה אוטומטית של ממצאים.
- `settleMs` קובע המתנה אחרי טעינה וגלילה; `timeoutMs` מגביל ניווט ופעולות. התאימו לאתר איטי. אין המתנה בלתי מוגבלת ל־networkidle.

## תרחישים: תפריט, FAQ וטופס

ראו [דוגמה מלאה עם כל סוגי התרחישים](../examples/fixture.config.json). צעדים נתמכים: `click`, `fill`, `press`, `expectVisible`, `expectHidden`, `expectText`, `expectAttribute`, `expectFocused`. `selector` הוא locator של Playwright, וצריך לזהות רכיב יחיד. `widths: [390, 768]` מגביל תרחיש לרוחבים מסוימים.

```json
{
  "name": "טופס יצירת קשר — הדמיה",
  "page": "/contact",
  "mocks": [
    { "method": "POST", "url": "/api/contact", "status": 200, "body": { "ok": true } }
  ],
  "steps": [
    { "action": "fill", "selector": "#email", "value": "qa@example.invalid" },
    { "action": "click", "selector": "form button[type=submit]" },
    { "action": "expectText", "selector": "[role=status]", "value": "הפנייה התקבלה" }
  ]
}
```

הוסיפו את האובייקט למערך `scenarios`. כל תרחיש מתחיל מטעינה מחדש; אין תלות במצב התרחיש הקודם. קריאת דמה מותאמת ל־**URL מדויק ומתודה מדויקת**, כולל query. דוגמת `/api/contact` נשארת חסומה ברשת גם כשהוגדרה לה תשובת דמה; הדפדפן מקבל תשובה מקומית. כל mock חייב להיקרא לפחות פעם אחת, אלא אם הוגדר `required: false`. מספר הקריאות נשמר בדוח. הגוף אינו נשלח לשרת, ואינו נשמר בדוח.

בזמן צעדי הפעולה ובדיקת המקלדת **כל בקשות הרשת נחסמות**, כולל GET, שליחת טופס רגילה, חלונות חדשים, `fetch`, XHR ו־beacon; רק mocks מפורשים מקבלים תשובה. גם WebSocket ו־Service Workers חסומים. אין אפשרות להפעיל שליחה אמיתית מהתרחישים. אם תפריט טוען נתונים בעת פתיחה, יש להגדיר גם עבורם mock; אחרת הכישלון עשוי לנבוע מסביבת הבדיקה. הצלחת טופס מדומה אינה מוכיחה שהשרת שולח מייל או שומר נתונים נכון.

טעינת עמודים, משאבים ובדיקת קישורים מבצעות GET/HEAD בלבד. אתר שמבצע מחיקה או יצירה ב־GET אינו יכול להיבדק בבטחה על בסיס המתודה בלבד: השתמשו בעותק מקומי/סביבת בדיקות והחריגו מסלולים כאלה. אין שימוש בפרופיל הדפדפן או בחשבון האישי שלכם. אל תכניסו סודות לכתובות או לקובץ ההגדרות.

הפניות עמודים נפתרות בנפרד, עם אימות scope לפני כל קפיצה, ואז הדפדפן נשלח ישירות ליעד. הפניות HTTP של משאבים בדפדפן נחסמות ומופיעות ברשימת החסימות: מנגנון routing עלול ליירט רק את הבקשה הראשונה בשרשרת. ניווט אוטומטי למסמך שלא תוכנן נחסם. אתרים שתלויים בהפניות כאלה, iframes, כניסה לחשבון, Service Workers או בקשות POST בזמן אתחול עשויים להיבדק חלקית.

## צילומים והשוואה חזותית

נשמר צילום של viewport לכל עמוד ורוחב, לכל מצב תרחיש, ועד 8 צילומי ראיות נוספים ועד 8 צילומי מיקוד לעמוד/רוחב. בצילום ראיה מתבצעת גלילה לרכיב תוך שימור מיקום הגלילה האופקי. אין צילום מלא של עמוד אינסופי. שדות `input`, `textarea` ו־`data-qa-private` ממוסכים כברירת מחדל. יש להוסיף selectors למידע אישי שמופיע במקומות נוספים; לוגים ושגיאות עשויים להכיל נתונים שהאתר עצמו מדפיס, ויש לבדוק לפני שיתוף הדוח.

**אין אישור אוטומטי לתמונת ייחוס.** כשלא קיימת תמונה מאושרת, הדוח מציין שההשוואה לא בוצעה. פתחו ובדקו צילום, העתיקו את המפתח המוצג בדוח, ואשרו אותו במפורש:

```sh
node src/cli.mjs approve --report runs/release-1/report.json --baselines qa-baselines --by "שם הבודק" --keys 0123456789abcdefabcd
```

המפתח לעיל הוא דוגמה; השתמשו במפתחות מן הדוח שלכם, מופרדים בפסיקים. באישור נשמרים שם המאשר, זמן, hash ותנאי הצילום. ריצה עתידית עם אותו URL/רוחב/שם תרחיש וסביבה תושווה לייחוס. שינוי בסביבת Chromium, מערכת הפעלה, מיסוך או viewport דורש בדיקה ואישור חדש; ייחוס לא תואם גורר קוד 2. החלפת תוכן תמונת הייחוס בלי אישור מזוהה לפי hash.

ההשוואה נעשית ברמת פיקסלים עם `pixelmatch`: `pixelThreshold` הוא סובלנות הבדל צבע לפיקסל; `maxDiffRatio` הוא החלק המותר מכלל הפיקסלים. שינוי מעל הסף מציג צילום נוכחי, ייחוס ו־diff כ**חשד לבדיקה אנושית**. שעונים, אנימציות, גופנים ותוכן דינמי עלולים לגרום להתראות שווא. הגדירו מיסוך עקבי והשתמשו באותה סביבה. כתובת localhost עם פורט משתנה מייצרת מפתח חדש.

## CI ושילוב בפרויקט קיים

| קוד | משמעות |
|---|---|
| 0 | הבדיקות הסתיימו ולא נמצא ממצא אוטומטי שחוצה את הסף |
| 1 | לפחות ממצא אוטומטי אחד בחומרה שנבחרה או גבוהה ממנה |
| 2 | הגדרות לא תקינות, שגיאת תשתית, עמוד/קישור שלא ניתן לבדוק, מפת אתר פגומה או ייחוס שאינו שמיש |

ספים: `info`, `low`, `medium`, `high`, `critical`, `none`. `none` מבטל כישלון בשל ממצאים; שגיאת תשתית עדיין מחזירה 2. חשדות, כולל טקסט חתוך ושינוי חזותי, מוצגים לבודק ואינם מכשילים את CI. הגעה למגבלת עמודים/קישורים שהוגדרה היא סריקה מוגבלת ומתועדת, ולא שגיאת תשתית. היעדר תמונת ייחוס הוא מצב לא מוכרע בהשוואה החזותית, ולא כישלון של בדיקות DOM.

```sh
npm ci
npx playwright install --with-deps chromium
npm run qa -- --config qa.config.json --out runs/ci
```

יש להפעיל קודם את שרת הפרויקט, להמתין לזמינותו, ולשמור את כל תיקיית `runs/ci` כארטיפקט גם כשהפקודה נכשלת. דוגמת GitHub Actions נמצאת ב־[examples/ci.yml](../examples/ci.yml).

אם כבר יש Playwright בפרויקט, אפשר להשתמש באותו browser, בזמן שהסורק יוצר contexts מבודדים משלו:

```js
import { test, expect } from '@playwright/test';
import { runScan } from './tools/rtl-qa/src/scanner.mjs';

test('בדיקת איכות אתר', async ({ browser }, testInfo) => {
  test.setTimeout(300_000);
  const report = await runScan({
    baseURL: 'http://localhost:3000',
    pages: ['/'],
    outDir: testInfo.outputPath('rtl-qa'),
    failOn: 'high'
  }, { browser });
  await testInfo.attach('qa-json', {
    body: JSON.stringify(report), contentType: 'application/json'
  });
  expect(report.exitCode).toBe(0);
});
```

התאימו את `webServer` בקובץ Playwright הקיים, ושמרו גרסה תואמת של `@playwright/test`. כדי להעביר את הכלי לפרויקט נוסף העתיקו את התיקייה בלי `node_modules`, תיקיות הדוחות ותמונות הייחוס של האתר הקודם, והריצו `npm ci`. החבילה כוללת lockfile לגרסאות מדויקות; אין צורך להחליף תשתית בדיקות קיימת.

## אתרון הבדיקה והאימות

```sh
npm test
npm run demo
```

`npm test` בודק scope והחרגות, קישורים ונרמול, sitemap מעגלי ופגום, שלושה רוחבים, כל משפחות התקלות שבאתרון, עמוד ביקורת תקין, תפריט תקין ושבור, FAQ במקלדת, טופס מדומה, ספירת בקשות לשרת חיצוני, חסימת פעולות, וייחוס מאושר/שונה/שנפגם.

`npm run demo` מפעיל את האתרון אוטומטית על `127.0.0.1:4173`, מפיק [דוח לדוגמה](sample-report/report.html), וסוגר את השרת. **יציאה 1 צפויה** בגלל התקלות המכוונות. אפשר גם להריץ `npm run fixture` במסוף אחד, ובאחר `npm run qa -- --config examples/fixture.config.json`.

## מגבלות ופרשנות

- גלילה אופקית מדווחת כמדידה מספרית; רכיבים החורגים מהמסך נמדדים משני הצדדים גם ב־RTL. גלריה רחבה, אזור גלילה או רכיב דקורטיבי עשויים להיות מכוונים. תוכן בתוך הורה בעל clipping/scroll אינו מדווח כחריגה עצמאית, ולכן אפשר גם להחמיץ מקרה אמיתי שם.
- חיתוך טקסט מבוסס scroll/client dimensions בשילוב overflow, ולכן הוא **חשד**. `ellipsis` ו־`line-clamp` מכוונים עשויים להופיע; canvas, pseudo-elements, Shadow DOM ו־iframes אינם נסרקים לעומק.
- בדיקות התוויות, alt, מבנה הכותרות ו־Tab הן בסיסיות. אין ניתוח איכות של alt, ניגודיות, קורא מסך, סדר קריאה מלא, התאמה לכל תקן או סריקת אבטחה. `alt=""` נחשב סימון דקורטיבי תקין, ולא נבדקת נכונות הבחירה.
- חיווי מיקוד ללא outline/box-shadow הוא חשד בלבד: עיצוב בעזרת גבול, צבע או pseudo-element עלול להיות תקין. אין בדיקה אוטומטית מלאה למלכודות מקלדת.
- קישור עם HTTP 200 שמציג תוכן שגוי או soft 404 אינו מזוהה בהכרח. עוגנים באותו עמוד נבדקים; עוגנים בעמוד אחר אינם מאומתים. קישורים חיצוניים אינם נבדקים.
- משאבים חסומים, lazy loading איטי, CAPTCHA, תכנים מותנים בכניסה, בקשות POST של GraphQL, דפי אינסוף, ונתונים משתנים יכולים לגרום לבדיקה חלקית או להתראות שווא. ראו רשימת חסימות, גבולות וכיסוי בדוח לפני הסקת מסקנות.
- הריצה ב־Chromium, locale עברי, DPR=1 ו־reduced motion. היא אינה מכסה Safari/Firefox, מכשיר מגע אמיתי, כל גודל מסך או מצב אנימציה רגיל.
- הכלי אינו הוכחה לנגישות מלאה, לאבטחה מלאה, או להתאמה לנטפרי. בדיקה בסביבת נטפרי ובדיקה אנושית נשארות נפרדות.

מקורות API ששימשו למימוש: [Playwright Network](https://playwright.dev/docs/network), [Route](https://playwright.dev/docs/api/class-route), [BrowserContext](https://playwright.dev/docs/api/class-browsercontext), [WebSocketRoute](https://playwright.dev/docs/api/class-websocketroute).
